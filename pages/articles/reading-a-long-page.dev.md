# 長い文章を読むための、画面の余白と小さな工夫

::: info サンプル記事
長文の記事ページを確認するための架空のデザインノートです。本文中の数値やCSSは表示用の例です。
:::

長い文章を読み始めるとき、最初から最後まで同じ調子で目を動かしているわけではない。冒頭を読み、少し先の見出しを眺め、気になるところで手を止める。途中で別のことをして、しばらくしてから同じ場所に戻ることもある。

記事の画面を考えるときも、そのような読み方を想像してみたい。最初の一画面が整っているだけでなく、途中から読み直せるか。表やコードが出てきても、本文に戻る場所を見失わないか。最後まで進んだとき、どんな話を読んだのか思い出せるか。

今回は、長い記事を一つ用意したつもりで、文章の構造と画面の見え方を順番に確かめていく。

## タイトルの次に、読む理由がある

タイトルには、どんな話題かを短く伝える役割がある。ただ、少し抽象的な題名だけでは、自分の知りたい話が含まれているか判断しにくい。そこで、冒頭の数段落で、この記事がどんな場面を扱うのかを示したい。

たとえば、余白についての記事なら、「読みやすくします」とだけ書くより、長い段落や横に広い表があるページを思い浮かべられるほうが、その先を読む理由になる。

導入が長すぎると、本題に入る前に疲れてしまうこともある。背景を一度に説明しきろうとせず、必要なことを本文の中で補っていく。書き手が知っている順番と、読み手が知りたい順番は、少し違うのかもしれない。

## 見出しを、途中から読むための目印にする

見出しだけを並べて読んだとき、文章の流れがなんとなくわかるだろうか。「はじめに」「詳細」「その他」といった短い見出しは便利だが、数が増えると違いを見分けにくくなる。

一つの節で何を話すかが決まっているなら、その内容を見出しに少し含めてみる。「余白」よりも「見出しの前後に余白を作る」のほうが、その節の話題を想像しやすい。長くしすぎる必要はないが、移動先の手がかりになる言葉は残したい。

### 同じ階層には、同じくらいの話を置く

大きな話題の途中に、細かい補足だけが同じ階層で並ぶと、どこまでが一つの話なのかわかりにくくなる。見出しの大きさを変える前に、文章のまとまりを見直すとよさそうだ。

### 目次から戻ってきても読めるようにする

目次を使う人は、必ずしも上から全部読んでいるわけではない。移動した直後の段落が「そのため」や「これについて」だけで始まっていると、何を指しているか探し直すことになる。

節の最初に話題を短く置き直す。それだけでも、途中から入った人が流れをつかみやすくなる。文章の重複を恐れて削りすぎるより、読む場所が変わることを考えて残す説明もありそうだ。

## 本文の幅を、実際の文章で確かめる

広い画面を使っていると、空いている場所を全部使いたくなる。けれど、横に長い行が続くと、次の行の先頭を探す動きも大きくなる。反対に幅を狭くしすぎると、短い言葉の途中で何度も折り返されてしまう。

どの幅がよいかは、文字の大きさや文章の内容によっても変わる。日本語だけの段落と、長い英単語やインラインコードが混ざった段落では、同じ幅でも印象が違う。

次のCSSは、幅や行間の考え方を説明するための例だ。数値をそのまま正解にせず、実際の文章を入れた画面で調整したい。

```css
.reading-example {
  max-width: 46rem;
  margin-inline: auto;
  padding-inline: 1.5rem;
  line-height: 1.9;
}
```

一つの短い段落だけで決めず、見出し、リスト、コードが続く場所も読む。少し下までスクロールすると、最初にちょうどよいと思った幅が、別の要素には合っていないこともある。

## 余白で、文章のまとまりを伝える

同じ文章でも、すべての要素が同じ間隔で並んでいると、話の切れ目が見えにくい。見出しの上は少し広く、見出しと最初の段落は近く。そんな関係があると、次の話題がどこから始まるかをつかみやすい。

ただし、余白を増やすほど読みやすくなるとは限らない。段落の間が開きすぎると、一つの話がばらばらに見える。リストの項目ごとに大きな余白があると、互いに関係のない内容のようにも見える。

ここでは、要素一つずつの間隔より、関係のあるものが一緒に見えるかを確かめたい。説明文とその直後のコード、表と表を読むための補足。それらが一まとまりに見えると、読む順番も伝わりやすくなる。

> 余白は、文章を置かなかった場所にも、文章の関係を持たせるために使える。

引用のように見た目が変わる要素も、周囲との間隔によって印象が変わる。本文に近すぎれば埋もれ、離れすぎれば別の話に見える。文章の意味と一緒に調整したい。

## 表にする前に、比べる軸を決める

項目がいくつか並んでいると、表にまとめたくなる。けれど、文章をただ箱に入れただけでは、横に長い段落が増えるだけかもしれない。表を使うなら、何と何を比べたいのかを先に決めたい。

| 要素     | 読むときの役割                 | 確認したい場面         |
| -------- | ------------------------------ | ---------------------- |
| 見出し   | 話題の始まりを知らせる         | 目次から途中へ移動する |
| 箇条書き | 並列の項目を見渡せるようにする | 項目の長さが異なる     |
| 引用     | 本文と違うまとまりを示す       | 複数の段落を含む       |
| コード   | 記述をそのまま読む             | 一行が長くなる         |

この表なら、左から「要素」「役割」「場面」と同じ順序で読める。項目の説明が長くなりすぎたら、表の外に出して段落にすることも考える。

狭い画面での表は、特に実物で見ておきたい。横に動かせることが伝わるか、本文全体まで横にずれないか。デスクトップで収まっているだけでは判断できない部分だ。

## コードの前後にも、読む順番を作る

コードブロックは、本文とは違う読み方をする場所になる。文章を読むときよりも、行の位置や記号に注意が向く。そのため、いきなり長いコードを置くより、先に何を見るための例なのかを短く伝えたい。

コードの後には、読み取ってほしい点を補う。全文を一行ずつ説明し直すのではなく、本文の話題とつながる部分を示す。コピーして使う例なのか、形だけを示す例なのかも、前後の文章でわかるようにしておく。

長い行を含む表示用の例として、次のようなパスを置いてみる。

```text
/articles/design-notes/a-long-example-path-for-checking-horizontal-scrolling-on-small-screens/reading-layout-example.md
```

ここで確認したいのは、パスの内容ではなく、長い一行があるときの画面の振る舞いだ。本文に戻ったとき、読み始める位置が変わっていないかも見ておきたい。

## 読み終わったところで、もう一度全体を見る

最後まで読んだら、少し上へ戻って見出しを眺めてみる。冒頭で予想した内容と、実際に読んだ内容は合っていただろうか。途中で話が飛んだように感じたところはなかっただろうか。

画面の確認も同じで、一つの要素だけを整えた後に、全体の流れを見直す。コードの背景や見出しの線が目立ちすぎて、本文より先に目に入ることがある。小さな調整でも、繰り返し現れる要素なら、長いページ全体の印象に影響する。

きれいに収まった一画面を作れたら、その先も読む。途中で離れてから、また戻ってみる。文章を置く人の都合だけでなく、読む人の時間の使い方まで想像できると、調整する場所が少し具体的になる。

長い記事のための工夫は、特別な装飾を増やすことだけではない。話題の順番を揃え、区切りを見つけやすくし、必要な場所でひと息つけるようにする。そうして整えた画面で、文章の続きを自然に読めたらうれしい。
