# 小さな個人サイトを、少しずつ育てる

::: info サンプル記事
この記事は、長文のレイアウトと記事一覧の表示を確認するための架空の制作記録です。
:::

個人サイトを作ろうと思うと、最初に考えることが意外と多い。何を書くか、どんな色にするか、記事をどこに置くか。気になるサイトを眺めているうちに、作り始める前から欲しいものだけが増えていく。

検索もほしいし、タグで絞り込めるようにもしたい。更新履歴や写真のページがあっても楽しそうだ。けれど、その全部を最初の公開条件にすると、肝心の文章を書くところまでなかなかたどり着かない。

今回は、短い自己紹介と記事の入口だけを用意するところから始めることにした。ここでは、架空の個人サイトを題材に、作る途中で考えたことを順番に残してみる。

## 最初のページに必要なものを決める

まず、このサイトを開いた人に何が伝わればよいかを書き出した。「誰のサイトか」「どんな文章があるか」「どこから読めるか」。最初の一ページでは、この三つがわかれば十分そうだった。

プロフィールを細かく書こうとすると、好きな技術やこれまでの活動も載せたくなる。ただ、記事を読みに来た人が毎回そこを通ると考えると、入口はもう少し短いほうがよい。詳しい紹介が必要になったら、その時点で置き場所を考えればいい。

紙に描いた最初の構成は、とても簡単なものになった。

```text
サイト名と短い紹介
────────────────────
記事のタイトル
日付・場所・読む時間・タグ
────────────────────
次の記事のタイトル
日付・場所・読む時間・タグ
```

この段階では、検索欄も大きな画像もない。それでも、文章への入口として必要な役割は説明できる。要素が少ないと、それぞれを置く理由も考えやすい。

## 空の画面だけでデザインを決めない

短いタイトルが一つだけ並んだ画面は、たいてい整って見える。ところが、実際に記事を増やしてみると、二行に折り返すタイトルや、文字数の違うタグが混ざってくる。日付と場所を並べた一行も、狭い画面では急に窮屈になる。

そこで、早い段階で長さの違う仮の記事を置いてみた。短いタイトル、中くらいのタイトル、少し説明的な長いタイトル。本文も、二段落で終わるものと、見出しがいくつも続くものを用意する。

ここで知りたいのは、理想的な一件が美しく見えるかだけではない。内容が変わっても、同じページとして無理なく読めるかどうかだ。文章を入れてから余白を調整すると、空の箱を眺めていたときには気づかなかった問題が見えてくる。

| 確認する内容 | 短いサンプル     | 長いサンプル               |
| ------------ | ---------------- | -------------------------- |
| タイトル     | 一行での位置関係 | 折り返した後の行間         |
| 本文         | 段落どうしの間隔 | 読み進めたときのリズム     |
| 記事一覧     | 一件のまとまり   | 複数件が続いたときの区切り |
| タグ         | 一つだけある場合 | 長さの違う二つが並ぶ場合   |

仮の文章にも、できれば小さな話の流れを持たせたい。同じ一文を何度も繰り返すより、見出しや引用を含む文章のほうが、読んでいる途中の感覚を確かめやすかった。

## 記事の情報を一か所に置く

記事一覧に表示するタイトルと、本文のタイトルを別々に管理すると、どちらかだけ直してしまいそうになる。日付やタグも同じで、記事が増えるほど、手で合わせる作業が増えていく。

このサイトのようにMarkdownに記事を書くなら、記事の先頭に情報をまとめる形がわかりやすい。たとえば、次のようなメタデータを文章と一緒に置く。

```yaml
title: 小さなサイトの制作メモ
description: 文章を置く場所を少しずつ整えた記録。
date: 2026-11-07
location: Tokyo
tags: [web, journal]
```

ファイルを開けば、一覧で使う情報と本文を続けて確認できる。記事を移したり、タイトルを変えたりするときも、探す場所が少なくて済む。

もちろん、情報を一か所に集めただけで、すべての間違いがなくなるわけではない。日付の書き方が違うこともあれば、説明文を書き忘れることもある。それでも、直す場所がはっきりしていると、確認の手順を短くできる。

## 装飾を増やす前に文章を読む

少し形になってくると、細かい見た目が気になり始める。カードの角をもっと丸くしたい。線をもう少し薄くしたい。ホバーしたときに動かしたい。どれも試してみたくなるが、まずは記事を上から下まで一度読んでみる。

読んでいると、見出しの直前だけ詰まって見えることがある。箇条書きの後に本文が続くと、話題が切り替わったことに気づきにくい場所もある。コードが出てくると、その前後だけ文章のテンポが変わる。

こういう違和感は、色を変えても解消しない。段落の長さや、行間や、本文の幅を少し調整したほうが、落ち着いて読めることも多かった。

> 一画面の印象だけでなく、最後の段落まで読んだときの疲れ方も見てみる。

この一文を、作業メモの先頭に置いておく。見た目の比較に夢中になると、何のためのページだったかを忘れやすいからだ。

## 作業を途中で止められる大きさにする

個人サイトの作業時間は、いつもまとまって取れるわけではない。平日の夜に少しだけ触ることもあれば、週末に文章だけ書くこともある。そのため、一回の作業で終わる単位を小さくしておきたい。

たとえば「記事ページを完成させる」では、どこまで進めればよいかが曖昧になる。「見出しの余白を確認する」「長い表がある記事を開く」「タイトルが二行になる一覧を確認する」なら、短い時間でも区切りをつけやすい。

作業の終わりには、次に見る場所を一行だけ残す。「スマートフォンの幅でコードブロックを見る」のように、再開した直後に手を動かせる書き方がよさそうだ。

1. 今日気になった点を一つ選ぶ。
2. その点を確認できる文章や画面を用意する。
3. 必要なところだけ直す。
4. 読み直して、次の作業を一行残す。

毎回大きく進める必要はない。止める位置がわかると、始めるときの負担も少し軽くなる。

## 機能を足す理由ができるまで待つ

記事が少ないうちは、一覧を順番に眺めるだけでも目的の文章にたどり着ける。検索を作りたくなっても、まずはどんな探し方に困っているのかを考えてみたい。

タイトルを忘れた記事を探したいのか、同じテーマの文章を続けて読みたいのか。あるいは、古い記録が下に埋もれることが問題なのか。同じ「探しにくい」でも、必要な手当ては違ってくる。

困り方が具体的になれば、小さな改善を選びやすい。タグの使い方を揃えるだけで済むかもしれないし、記事の説明を少し書き足したほうがよい場合もある。先に機能の名前を決めるより、読む人の動きから考えたい。

## また文章を置きたくなる場所にする

サイトを作る楽しさには、細部を好きなように決められることがある。余白や文字の大きさに迷う時間も、それ自体が面白い。ただ、整える作業だけで疲れてしまうと、新しい文章を置く気持ちが遠のいてしまう。

一つ記事を書いたら、一覧に自然に加わる。開けば、見出しやコードがいつもの形で読める。そんな当たり前の流れを、少しずつ確かにしていく。

次にこのサイトを開くとき、最初に考えるのが「何を直そう」だけでなく、「今日は何を書こう」でもあってほしい。いまのところは、そのくらいの完成を目指している。
